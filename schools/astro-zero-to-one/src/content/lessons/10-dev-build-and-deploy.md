## 1. 生命周期三部曲：dev、build 与 preview

在第二关中，我们简要了解了 `package.json` 中的脚本命令。现在，让我们深入理解它们之间的协作关系与生命周期差异：

```text
               npm run dev
源代码 (src/) ─────────────► 本地开发服务器 (实时热更新，用于编码调试)
     │
     │ npm run build
     ▼
静态产物 (dist/) ───────────► 1. npm run preview (本地启动 Web 服务器模拟生产)
                           └──► 2. 部署上线 (推送到 GitHub Pages / Vercel 等)
```

### (1) `npm run dev`：开发模式
- **核心能力**：Astro 会监听 `src/` 目录中的所有文件变动。只要你按下保存键，浏览器中的网页就会实时热更新，无需手动刷新。
- **开发工具栏（Dev Toolbar）**：在开发模式下，页面底部会出现 Astro 官方的开发小工具，可以帮你直观检查页面上有哪些客户端群岛、检测无障碍（a11y）问题等。
- **时机**：编写代码、调试页面样式与逻辑的唯一主战场。

### (2) `npm run build`：生产构建
- **核心能力**：
  1. 读取全部页面、组件与数据，执行严格的 TypeScript 类型检查与 Zod 模式校验。
  2. 将所有 `.astro` 页面与动态路由预渲染为纯静态 HTML 文件。
  3. 压缩并打包 CSS，优化 `src/assets/` 中的图片。
  4. 将所有可直接部署的文件输出到项目根目录下的 **`dist/`** 目录中。
- **时机**：准备发布上线、或需要检验是否存在编译/类型错误时运行。

### (3) `npm run preview`：生产预览（初学者最易混淆的陷阱！）
- **核心能力**：在本地启动一个轻量级的 HTTP 静态服务器，直接提供 `dist/` 目录中的文件访问。
- **★ 核心机制辨析**：
  > **`npm run preview` 预览的永远是“上一次执行 `npm run build` 时的代码状态”！**
  > 如果你在 `src/` 中修改了代码，直接在 `preview` 模式下刷新浏览器，**你的修改绝对不会出现**！因为你还没有重新执行 `npm run build` 来更新 `dist/` 目录！
- **时机**：在把代码推送到生产服务器之前，用于在本地确认打包后的静态文件是否一切正常。

## 2. 生产部署上线：静态托管的极致便利

因为 Astro 默认产出的是纯粹的静态 HTML、CSS 和图片（存放在 `dist/` 文件夹中），这使得 Astro 站点具备**天然的便携性**：
- 它不需要任何昂贵的 Node.js 服务器或复杂的数据库支持；
- 它可以零成本托管在世界上任何静态 Web 服务器上！

### 统一的部署契约：
无论你选择哪个平台，配置通常只需要填两行：
- **构建命令 (Build Command)**：`npm run build`
- **输出目录 (Publish Directory / Output Directory)**：`dist`

### 常见部署目的地：
1. **GitHub Pages**：适合开源项目、个人博客与文档站。配合 GitHub Actions，每次 git push 即可全自动构建并发布。
2. **Cloudflare Pages / Vercel / Netlify**：一键绑定 GitHub 仓库，提供全球边缘 CDN 加速、自动化 HTTPS 证书与极其极速的访问体验。
3. **自有服务器（Nginx / Caddy / Docker）**：只需将 `dist/` 目录打包拷贝到服务器，配置好静态文件映射即可。
